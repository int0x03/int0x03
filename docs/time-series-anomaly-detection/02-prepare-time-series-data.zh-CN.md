# 第 2 课：建立可信的时间线

[English]({{ '/time-series-anomaly-detection/lessons/02-prepare-time-series-data/' | relative_url }})

## 检测器找到的可能只是脏数据

服务每分钟导出一次读数。下面这段数据看起来很异常：

| 时间戳 | 请求量 | 实际发生了什么？ |
| --- | ---: | --- |
| 10:00 | 98 | 有效读数 |
| 10:01 | 102 | 有效读数 |
| 10:01 | 102 | 重复导出 |
| 10:03 | 0 | 10:02 缺失；采集器用零作为默认值 |

如果没有数据约定，模型会自信地检测导出器行为，而不是服务行为。

## 首先定义时间轴

计算任何分数之前，先回答以下问题：

1. 时间戳是否唯一、有序，并采用一种有文档说明的时区？
2. 数据由事件触发，还是应该每秒、每分钟或每小时采样？
3. 缺失读数表现为不存在、`null`、零，还是 `-1` 之类的特殊值？
4. 数据是否会延迟到达，并修订刚刚过去的记录？
5. 夏令时或时钟调整是否造成了重复或缺失的本地时间？

填补缺口时，要保留一列**实际观测/未观测掩码**。插补值是估计，不是测量。长时间缺失本身可能就是运维事件，不能总是插值成一条看似正常的平滑曲线。

## 删除成分之前，先看清它们

一个实用的思维模型是：

```text
观测序列 = 水平/趋势 + 重复的季节性 + 剩余项

请求量
  ^       午间峰值      午间峰值      午间峰值
  |      /\          /\          /\       ← 每日季节性
  | ____/  \________/  \________/  \____
  +--------------------------------------> 时间
        逐渐增长 →                         趋势
```

剩余项通常称为**残差**。残差不一定只是噪声：事故、日历效应或模型设定错误都可能留在其中。

用多个时间尺度观察原始序列。一小时能显示尖峰；几周能显示每日和每周模式；几个月可能显示业务增长或产品迁移。

## 按时间划分，绝不随机打乱

```text
过去                                                         未来
|----------- 训练 -----------|----- 验证 -----|----- 测试 -----|
 拟合基线和变换                   选择阈值          只报告一次
```

- **训练集**估计正常行为和模型参数。
- **验证集**选择窗口、超参数和告警阈值。
- **测试集**代表更晚且从未参与选择的时段，用于最终比较。

如果一次划分太依赖某个特定星期，可以使用滚动回测。每一折都必须在较早数据上训练，在较晚数据上评估。

## 未来信息泄漏长什么样

生产检测器在 10:00 不可能知道 10:01。以下操作都会泄漏未来信息：

- 把所有时间戳随机打乱后分配给训练集和测试集；
- 使用整个时间线的均值归一化所有数据；
- 使用会包含未来数值的居中滚动平均；
- 用缺口之后的下一个已知观测填补缺失；
- 反复查看最终测试集并调整阈值。

每个缩放器、插补器、季节基线、特征和模型都只能使用决策时已经获得的信息。离线评估还要模拟生产中的延迟和迟到数据策略。

## 本课检查清单

- [ ] 记录时间戳、时区、采样、延迟和缺失值规则。
- [ ] 解决或明确标记重复记录与缺口。
- [ ] 在多个时间尺度上检查趋势和季节性。
- [ ] 建立按时间排序的训练、验证和测试时段。
- [ ] 验证每个特征只使用评分时已经获得的信息。
