# 第 7 课：选择阈值并评估事件

[English]({{ '/time-series-anomaly-detection/lessons/07-thresholds-and-evaluation/' | relative_url }})

## 分数还不是告警

同一个检测器可以用不同方式服务两个团队：

```text
分数         /\       /\
阈值 1  -----------        发现更多，告警也更多
阈值 2  -----^-----        发现更少，告警也更少
时间   --------------------------------------------->
```

模型产生**异常分数**。决策规则把这个分数与阈值、持续时间规则、抑制策略以及业务上下文结合起来。改变阈值并不等于重新训练模型。

## 在验证数据上校准

使用时间上更晚的验证时段选择阈值，然后在查看测试结果之前冻结它。实用目标包括：

- 在每周误报不超过五次的前提下，最大化事件召回率；
- 最小化业务成本，其中漏掉事故比调查一次告警代价更高；
- 达到规定的事件精确率或检测延迟；
- 没有标签时先采用较高的分数分位数，再人工抽样审查告警。

不要只因为某个库要求，就随意填写异常占比。它代表对异常发生率的假设，必须验证。

## 把相邻异常点变成事件

假设一次故障持续五分钟：

```text
真实事件： ......[========== 一次事件 ==========]......
告警：     ..........^..^..^............................
逐点视角：            检测到三个点
事件视角：            检测到一个事件，应合并三个告警
```

需要记录一套事件匹配规则：

1. 合并间隔小于指定值的告警。
2. 预测事件与真实区间重叠时视为匹配，也可以设置允许提前或延后的容差。
3. 每个真实事件最多匹配一次。
4. 未匹配的预测事件算误报，未匹配的真实事件算漏报。

比较模型之前必须固定这套规则。

## 衡量运维人员真正感受到的结果

在事件计数中，令真阳性（True Positive，$$TP$$）表示检测到的真实事件，假阳性（False Positive，$$FP$$）表示误报事件，假阴性（False Negative，$$FN$$）表示漏报事件：

$$
\operatorname{precision} = \frac{TP}{TP + FP}
$$

$$
\operatorname{recall} = \frac{TP}{TP + FN}
$$

- **精确率**回答：系统告警时，有多少事件是真的？
- **召回率**回答：所有真实事件中，检测到了多少？
- **检测延迟**衡量从事件开始到首次有效告警的时间。
- **告警量**衡量每天或每周需要审查多少次。

逐点准确率通常具有误导性：当事故很少时，永远预测“正常”也可能达到 99.9% 的准确率，却一个事故都发现不了。

## 公平评估

- 测试时段必须晚于训练集和验证集。
- 应同时包含平静期、繁忙期、季节变化和已知事故。
- 在相同告警预算或运维成本下比较所有候选方法。
- 事件很少时要说明不确定性；一个事件就能大幅改变召回率。
- 按异常类型检查误报和漏报，不要只相信一个汇总数字。

## 本课检查清单

- [ ] 定义分数方向和完整决策规则。
- [ ] 在验证数据而非测试数据上选择阈值。
- [ ] 定义事件合并、时间容差和一对一匹配。
- [ ] 报告事件精确率、召回率、延迟和告警量。
- [ ] 使用相同时段和告警预算比较方法。
