# 第 8 课：让检测器走进生产环境

[English]({{ '/time-series-anomaly-detection/lessons/08-production-and-llms/' | relative_url }})

## 模型只是整个系统中的一个方框

```text
指标 → 质量检查 → 特征 → 数值检测器 → 分数 → 决策规则
  │                                          │
  └── 数据可用性监控                     事件 + 证据
                                              ↓
日志 + 发布记录 + 操作手册 → 上下文检索 → 解释 → 运维人员
                                              │
                                         反馈与标签
```

系统需要为每个箭头指定负责人、降级行为和可观测性。在笔记本里很准确，却在数据停止到达时悄无声息的检测器，还不能投入生产。

## 监控你的监控系统

至少跟踪四个层次：

| 层次 | 示例信号 |
| --- | --- |
| 输入 | 延迟、缺失率、重复、范围、模式和单位变化 |
| 分数 | 分数分布、季节模式、超过阈值的比例 |
| 告警 | 每日事件数、抑制比例、受影响服务、调查工作量 |
| 结果 | 已确认事故、误报、漏报、检测延迟 |

告警数突然降为零，既可能表示服务健康，也可能表示流水线损坏。心跳和数据质量告警应该独立于异常模型。

## 面对漂移，需要响应策略

**数据漂移**表示输入或分数分布发生变化；**概念漂移**表示观测值与真实事故之间的关系发生变化。二者都不等于“必须立即重训”。首先判断原因是预期增长、传感器或单位变化、发布、事故，还是模型遗漏的季节性。

明确谁可以重训、哪些历史数据可用、必须通过哪些评估、怎样重新校准阈值以及如何回滚。模型、特征、数据和阈值版本必须一起保存。

## 基础模型与语言模型承担不同任务

**时序基础模型**在大量数值序列上预训练。它可以提供预测、预测区间或嵌入，再供数值检测器使用。它可能有助于冷启动，但仍然需要领域评估、延迟检查和阈值校准。

通用大语言模型（Large Language Model，LLM）更适合放在经过校准的数值检测器**之后**。它可以把事件与授权日志、发布记录、指标说明和操作手册结合起来，用于：

- 概括什么在何时发生了变化；
- 关联相关告警；
- 检索可能适用的操作步骤；
- 起草带有证据链接的分诊记录。

它不应该编造测量值、悄悄修改阈值，也不能在没有证据时断言根因。

## 让辅助分诊可以审计

应传递结构化上下文，而不是一张无法解释的截图：

```text
事件：开始/结束时间、分数、阈值、受影响变量
证据：来源、时间戳、摘录或汇总
变化：发布与配置变更
输出：摘要、假设、引用证据、不确定性、后续检查
```

保护凭据和个人数据，把检索范围限制在运维人员本身的权限内，明确标记生成的假设，并保留原始证据链接。回滚或通知值班人员等高影响操作，必须经过确定性规则或人工批准。

## 分阶段上线

1. **历史回放：**在历史数据上运行，不产生运维影响。
2. **影子模式：**为实时数据评分，但不通知响应人员。
3. **有限上线：**采用保守阈值，只通知一个团队或服务。
4. **全面上线：**告警量和事件效果达到要求后再扩大范围。
5. **定期复查：**持续检查漂移、漏报、误报和运维反馈。

上线期间继续运行简单基线。它既是降级方案，也能尽早提醒我们复杂模型已经不再值得其成本。

## 最终检查清单

- [ ] 为数据、模型、阈值和事故响应指定负责人。
- [ ] 分别监控输入、分数、告警和结果健康度。
- [ ] 对重训和回滚流程进行版本管理与测试。
- [ ] 使用 LLM 提供带证据的辅助，而不是校准数值分数。
- [ ] 分阶段上线，并保留经过验证的降级方案。
