#基于 agent skill 的自动化问题诊断框架

最近一直在小规模实践和思考如何在大模型时代做自动的生产环境问题分析诊断. 
本文的前提是生产环境的数据收集, 分析, 整理, 告警等基础设施已经完善, 使用 Agent 来代理人工分析诊断问题的过程, 并不断优化和迭代诊断的能力. 

虽然大家的终极信念都是 AI 自动运维, 排除 human-in-the-loop, 但是现阶段这还是一个理想, 尤其在生产环境, 一次误操作, 可能比诊断不出来的风险更大. 

相比于原来的工具都部署在生产环境, 现在的 Agent 大多数都部署在本地 corp 环境. 

核心设计理念:
1. 大模型有通用的分析诊断能力, 尤其对于开源产品和通用的技术栈
2. 公司内部的相对静态信息, 需要通过 RAG 或者 skill 来获取, RAG 和 skill 不断添加, 迭代更新
3. 公司内部的相对动态信息, skill 可以调用公司的 API 或者 MCP 工具来获取, 主要对接 metrics, logs, traces, topology, config 等等.

所以基本流程是:
告警 -> agent -> skill/RAG -> API/MCP -> metrics/logs/traces/topology/config. 

会涉及到 agent 的编排, Memory 的共享, skill 的层次结构组织及更新, RAG 文档的更新迭代, API 和 MCP 的权限和认证等. 

使用 agent + skill 都方式, 其实是把之前把人做的事情都转成 agent 要做的事情
1. 把人的判断分析改成 大模型的分析判断
2. 把人要做的收集整理获取信息改成 agent 要做的收集整理获取信息, agent 可以做并行并且更快. 
3. 大模型不知道的公司内部相对静态信息, 要通过 RAG 或者 skill里面的信息获取. 
4. 大模型不知道的公司内部相对动态信息, 要通过 skill 里面使用的 api 或者 MCP 工具来获取.

当然人做的要慢, 思维也慢, agent 可以做大规模并行收集, 分析, 验证.

难点:
1. 人喜欢一图胜千言, 迅速浏览一批dashboard, 就能发现可疑的异常点, 但agent 不擅长读 metrics 图表, 即便喂给它原始数据, 它需要借助其它工具来分析, 并且现在没有现成的工具来做数据的 insights, 更不要提并行看多图的效率. 
2. 要把之前给人看的各种成熟的 dashboards, 变成 agent 能够理解的形式, 对于短文本问题不大, 但是对于图表, 要做非常大的改动. 
3. 授权和认证, 之前的都是做在各种工具上的, 登录, 认证, 授权都是以人为基础做的. 现在 agent 虽然可以继承人的身份, 但是对于人的基于UI的双因素认证和基于 API 或者 MCP 的认证完全不一样. 
4. 对于这个诊断系统的操作边界, 在skill 里面要加以约束, 但要做到边界清晰, 要从 API 和 MCP 层面做强制鉴权和授权. 

对于事后要做的事情:
1. 根据之前的经验, 人通常只会记录关键的结论, 并且主动漏掉走弯路的部分, 一旦事情解决, 没有动力去记录过程, 但是 agent 可以把整个过程都记录下来, 并且可以在后续的分析中使用.
2. 事后整理的 trajectory 可能要用到实时的数据, 这些在当时实时的数据要同步保留, 供以后重跑验证skill的能力. 

从实施的角度来讲, 就是有一个地方要保留有用的skill, 并且可以不断的升级迭代. 
另外要根据skill的scope, 来做分层, 分类整理, 便于管理和调用. 
至于agent 的并行能力, 现在 claude 和 opencode 提供的都在一定程度够用.
